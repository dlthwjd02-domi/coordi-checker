# 코디 체커

상하의 상품 URL을 넣으면 이미지에서 실제 색을 뽑아 어울리는지 점수로 알려주고,
여행지 기온까지 맞춰 보는 도구.

**바로 쓰기 → https://dlthwjd02-domi.github.io/coordi-checker/**

설치가 필요 없다. 링크를 열면 그 화면에서 바로 돌아간다.

## 어떻게 서버 없이 돌아가나

브라우저는 다른 사이트의 HTML·이미지를 직접 읽을 수 없다 (CORS, 핫링크 차단).
그래서 **가져오기만** Cloudflare Worker 가 대신하고, **색 추출·패턴 판별·배경 제거는
브라우저가 Canvas 로 직접** 한다. 기온·지역 검색은 Open-Meteo / OpenStreetMap 을
브라우저에서 바로 부른다 (둘 다 CORS 를 열어둔다). 정적 사이트라 잠들지 않고 바로 열린다.

구조와 옮긴 과정, 파이썬과의 대조 결과는 [WEB.md](WEB.md) 에 있다.
Worker 는 `worker/` 에 있고 `cd worker && npx wrangler deploy` 로 올린다.

## 내 맥에서 돌리기 (선택)

**무신사·스마트스토어 주소를 그대로 쓰고 싶으면 이게 답이다.** 그 쇼핑몰들은 데이터센터 IP 를
막으므로 워커로는 못 가져오지만(무신사는 `robots.txt` 로 명시), 내 맥에서 가져오면 평범한
방문이라 그냥 된다.

**로컬 서버가 웹 앱(`docs/`)을 그대로 서비스한다.** 켜고 `http://localhost:8787` 로 열면
같은 화면이 뜨는데, 가져오기를 내 맥이 하므로 무신사 주소도 그대로 들어간다.
같은 출처라서 브라우저 권한이나 CORS 문제가 없다.

github.io 페이지도 로컬 서버를 찾아보긴 한다(찾으면 "내 맥 연결됨" 배지). 다만 크롬 138+ 는
https 페이지가 로컬 주소로 요청할 때 **로컬 네트워크 접근 권한**을 묻고, 사파리는 막을 수 있다.
확실하게 쓰려면 `localhost:8787` 로 여는 쪽이 낫다.
안내: https://dlthwjd02-domi.github.io/coordi-checker/local.html

1. [폴더 내려받기](https://github.com/dlthwjd02-domi/coordi-checker/archive/refs/heads/main.zip) 후 압축 풀기
2. `start.command` 더블클릭 — 브라우저가 자동으로 열린다

처음 한 번은 `.venv` 를 만들고 꾸러미를 깔아서 1~2분 걸린다. 맥 전체 파이썬 설정은 건드리지 않는다.
"확인되지 않은 개발자" 경고가 뜨면 `start.command` 를 우클릭 → 열기 로 한 번만 실행하면 된다.

```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python server.py        # http://localhost:8787
pkill -f server.py                # 종료
```

의존성은 `requests`, `Pillow` 뿐이다. 서버는 `127.0.0.1` 에만 붙는다.

**같은 로직이 두 곳에 있다** — `server.py`(파이썬)와 `docs/core.js`(브라우저).
웹 쪽이 주된 구현이고, 파이썬 쪽은 로컬 실행용으로 남겼다. 한쪽을 고치면 다른 쪽도 봐야 한다.
양자화 방식이 달라서 대표색이 몇 단계씩 다를 수 있다 — 대조 결과는 [WEB.md](WEB.md) 에 있다.

## 쓰는 흐름

화면은 위에서 아래로 순서대로 따라가게 짜여 있다.

1. **어디로, 언제 가나요?** — 맨 위 전체 폭 카드. 나라·도시를 검색하거나 칩으로 고르고 월을 선택한다.
   오른쪽에 그 달 기온과 날씨 픽토그램, 옷차림 조언이 바로 나온다.
2. **상품 URL** — 아우터 / 상의 / 하의 / 신발 네 칸. 상의·하의만 있어도 진단이 나온다.
   상품 카드의 **다른 색 N개** 버튼으로 원하는 컬러웨이를 고른다.
3. **코디 보드 → 핏 뷰 → 어울림 진단** 이 오른쪽에 차례로 쌓인다.
4. 코디는 브라우저에 저장해서 여러 조합을 비교할 수 있다.

### 날씨 픽토그램

인라인 SVG 6종(`sun` `hot` `cloudSun` `rain` `snow` `cold`)을 직접 그려 넣었다.
외부 아이콘을 안 받아오므로 인터넷 없이도 뜬다. 구름은 원 3개와 둥근 사각형을 겹쳐 만들어서
어느 브라우저에서나 같은 모양으로 나온다.

그 달 픽토그램은 눈 5일 이상 → `snow`, 평균 -10°C 이하 → `cold`, 비 13일 이상 → `rain`,
평균 27°C 이상 → `hot`, 비 8일 이상 → `cloudSun`, 나머지는 `sun` 순으로 고른다.
7일 예보는 강수확률 50% 이상이면 `rain`(최고 1°C 이하면 `snow`), 25% 이상이면 `cloudSun`.

| 도시 | 결과 |
|---|---|
| 밴쿠버 1월 (3.6°, 비 16일) | `rain` |
| 캘거리 1월 · 밴프 1월 · 서울 1월 | `snow` |
| 이누빅 1월 (-23.3°, 눈 14일) | `snow` |
| 방콕 8월 (29°, 비 26일) | `rain` |
| 통영 8월 (27.8°) | `hot` |
| 경주 10월 (16.9°, 비 11일) | `cloudSun` |

색이 엉뚱하게 잡히면 세 가지 길이 있다.

- 상품 카드 아래 **팔레트 5칸** 중 원하는 색 클릭
- **다른 색 N개** 에서 다른 컬러웨이 사진 선택
- **컬러 피커**로 색을 직접 지정 (스포이드로 화면 아무 픽셀이나 찍으면 됨). 되돌리려면 "자동"

## 여행지 기온

도시를 검색하거나 칩(밴쿠버·토론토·몬트리올·캘거리·서울·부산·도쿄·방콕·다낭·파리·뉴욕)으로 고르고 월을 선택한다.
기온은 **최근 3년 해당 월의 실제 관측치 평균**이다. 이번 달을 고르면 7일 실제 예보도 같이 나온다.

데이터는 Open-Meteo (API 키 불필요). 조회 결과는 `cache/clim_*.json` 에 저장된다.

- geocoding-api.open-meteo.com — 도시 검색 (`language=ko`)
- nominatim.openstreetmap.org — 도시 검색 보조
- archive-api.open-meteo.com — 과거 관측 (ERA5)
- api.open-meteo.com — 7일 예보

### 지역 검색

한글로 어느 나라든 찾을 수 있게 하려면 손이 좀 간다. Open-Meteo 지오코딩은 접두어 매칭이라
"경주"로는 아무것도 안 나오고(한국 도시는 "경주시"로 등록), "강릉"은 북한 지명이 먼저 나왔다.
Nominatim 단독으로는 "경주"가 기차역, "통영"이 식당으로 잡혔다. 그래서 다음을 다 한다.

1. **질의 확장** — 한글이면 접미사 `시·군·구·특별자치시·특별자치도`를 붙인 질의를 함께 던진다.
2. **로마자 변환** — 한국어 색인에 아예 없는 지명이 있다 (통영 → DB에 `Tongyeong` 만).
   한글 음절을 분해해 국어의 로마자 표기법으로 바꿔 같이 검색한다. 찾으면 사용자가 적은 한글로 표시한다.
3. **두 곳 동시 조회** — Open-Meteo(한국어 이름에 강함)와 Nominatim(자유 입력에 강함)을
   병렬로 던지고 합친다. 순차로 하면 한 검색에 3초씩 걸리므로 병렬이 필수다.
4. **종류 필터** — Open-Meteo 는 `feature_code` 가 `PPL·ADM·ISL` 로 시작하는 것만,
   Nominatim 은 `city·town·village·county·state·island` 등만 남긴다. 공항·역·학교·식당은 버린다.
5. **순위** — 인구수 기준. Nominatim 은 인구수가 없어서 종류별 가중치를 준다(city 3M, town 300k…).
   "대한민국, 경주" 처럼 나라를 같이 적으면 그 나라를 위로 올린다. 적은 이름과 그대로 맞으면 가점.
6. **중복 병합** — 좌표가 겹치거나 같은 나라의 같은 이름이면 한 곳으로 묶고, 점수는 센 쪽을 따른다.
   이걸 안 하면 두 곳이 같은 도시를 찾았을 때 점수 낮은 쪽이 살아남아 순위가 뒤집힌다.

| 검색어 | 결과 |
|---|---|
| 경주 / 대한민국, 경주 | 경주시 (대한민국 · 경상북도) |
| 통영 | 통영 (대한민국 · 경상남도) — 로마자로 찾음 |
| 강릉 | 강릉시 (대한민국 · 강원도) 먼저, 북한 강릉은 뒤로 |
| 서귀포 · 속초 · 춘천 · 거제 · 양양 | 모두 1순위로 정확 |
| 밴프 / Banff | 밴프 (캐나다 · 앨버타 주) — 영국 Banff 보다 위 |
| San Sebastian | Donostia / San Sebastián (스페인) |
| 휘슬러 · 옐로나이프 · 이누빅 · 치앙마이 · 레이캬비크 | 모두 정확 |

한글 표기가 DB와 다르면 못 찾는다. 캐나다 Banff 는 Open-Meteo 에 "밴프"로 들어 있어서
"반프"로는 안 나온다. 그때는 다른 한글 표기나 영어 이름을 쓰라고 안내한다.

### 옷차림 밴드 (평균기온 기준)

27+ 한여름 / 22+ 초여름 / 17+ 봄가을 / 11+ 늦가을 / 1+ 초겨울 / -5+ 한겨울 / -12+ 강추위 / 그 아래 극한

밴쿠버 1월(3.6°C)이 "한겨울·패딩 필수"로 나오는 게 과했어서 초겨울 경계를 4→1°C, 한겨울을 -3→-5°C로 내렸다.

### 조건부 조언

- 일교차 11도 이상 → 레이어링
- 눈 5일 이상 → 방수 신발 / 비 13일 이상 → 방수 아우터 / 비 8일 이상 → 우산
- 최저 영하 8도 이하 → 실내 과난방 대비 반팔 이너
- 평균 27도 이상 + 비 13일 이상 → 빨리 마르는 소재

지금 고른 옷과도 연결된다. 12°C 미만인데 아우터가 없으면 경고, -5°C 미만이면 "패딩에 가려지니 색만 안 튀게",
22°C 이상인데 아우터가 있으면 "이 기온이면 아우터는 안 입게 된다".

## 아더컬러 추출

상품 페이지에는 이미지가 80장씩 있다. 그중 **메인 사진 아래 썸네일 줄(다른 색상)만** 골라내는 게 핵심이다.

1. **수집** — `<img>` 의 `src`·`data-src`·`data-original`·`data-lazy`·`srcset`(최대 해상도)에
   `__NEXT_DATA__` 같은 JSON 덩어리 안의 URL까지 훑는다. 태그의 `class`·`alt`·`id`·`title` 도 힌트로 같이 챙긴다.
2. **정크 제거** — 로고·아이콘·배너·국기·SNS 버튼·쿠폰·추적 픽셀을 경로와 호스트로 걸러낸다.
3. **모양 묶음** — URL에서 숫자와 해시를 `#` 로 치환해 "모양"만 남기면 색상만 다른 이미지가 한 덩어리가 된다.
   파일명 전체가 해시로 보이면(8자 이상 영숫자에 숫자 포함) 통째로 치환한다.
4. **그룹 선택** — 경로에 `chip`·`color`·`option`·`swatch` 가 있으면 +100,
   `class`/`alt` 에 `xzoom`·`gallery`·`상품 이미지` 같은 갤러리 표시가 있으면 +60, 메인 이미지 포함 +20, 장수만큼 가점.
   2~30장짜리 그룹 중 최고점을 쓴다.
5. **색으로 합치기** — 후보마다 대표색을 뽑아 RGB 거리 14 이하는 한 장만 남긴다.
   같은 색의 앞모습·뒷모습·디테일컷이 하나로 합쳐진다. 8개씩 병렬로 내려받아 1초 안에 끝난다.

필터가 엉뚱하게 고를 경우를 위해 **전체 N장 보기** 버튼을 남겨뒀다.

| 아임웹 (mynewpage.co.kr) | 81장 | 5개 — 갤러리 4색(베이지·브라운·라이트그레이·다크브라운·다크네이비) + 대표 |

**색상 칩이 가장 정확하다.** 모델 착용샷은 피부·배경·소품 색이 섞이는데 칩은 옷 색만 있다.

### 아임웹에서 막혔던 것

세 가지가 겹쳐 있었다.

1. 대표 이미지는 `cdn.imweb.me`, 갤러리는 `cdn-optimized.imweb.me` 였다.
   "메인과 같은 호스트만" 조건 때문에 갤러리가 통째로 버려졌다 → 도메인 뒤 두 자리(`imweb.me`)만 비교.
2. 파일명이 `da580646a7dbc.jpg` 같은 해시라 숫자만 지워도 모양이 전부 달랐다 → 해시 파일명은 통째로 치환.
3. 사이트의 모든 이미지가 `/upload/<사이트ID>/<해시>.jpg` 를 써서 갤러리 8장이 기획전·상세·관련상품 65장과
   한 덩어리(73장)로 묶여 크기 제한에 걸렸다 → 갤러리 표시가 붙은 것은 같은 경로여도 따로 묶는다.

`COLOR_HINT` 정규식이 파일에 두 번 정의돼 있어 `thumb` 이 포함된 옛 버전이 이기고 "thumbnail" 경로를
색상 칩으로 착각하던 것도 같이 고쳤다.

## 색 추출 방식

Pillow로 이미지 가운데(가로 18~82%, 세로 12~92%)를 잘라 배경·워터마크를 피하고,
스튜디오 흰 배경과 밝은 회색 배경을 걸러낸 뒤 MEDIANCUT으로 5색까지 양자화한다.
걸러낸 픽셀이 40개 미만이면(흰 옷을 흰 배경에서 찍은 경우) 원본 전체로 되돌린다.

## 핏 뷰 — 실제 사진으로 맞춰 보기 (photo-match 브랜치)

그래픽·스트라이프 옷은 대표색 하나로 볼 수 없어서, 사진 자체를 맞춰 보는 화면을 붙였다.
진단 카드 위에 **핏 뷰** 카드가 생기고 두 가지 모드가 있다.

- **나란히** (기본) — 상하의 사진을 크게 나란히 놓고 각 사진 아래에 색 비중 띠를 깐다.
  패턴 옷은 띠가 여러 칸으로 나와서 어떤 색들로 이뤄졌는지 바로 보인다.
- **합성** — 배경을 지운 사진을 위아래로 겹쳐 한 착장처럼 본다.
  상의·하의 각각 크기·위아래·좌우 슬라이더가 있어서 옷이 보이는 구간을 맞출 수 있다.
  잘라낸 사진의 모델이 한쪽으로 치우쳐 있는 경우가 많아 좌우 조정이 필요하다.

### 배경 제거

`/api/cutout` 이 스튜디오 단색 배경을 지워 투명 PNG로 만든다. 학습 모델 없이 Pillow만 쓴다.

테두리를 4픽셀 간격으로 훑어 최빈색을 씨드로 잡고, 허용범위(26) 안에 드는 샘플이 55% 이상이면
지울 수 있는 배경으로 본다. 그 다음 테두리에서 시작해 배경색으로 이어진 영역만 지우므로
옷 안쪽의 흰색은 남는다. 마지막으로 남은 영역의 경계로 잘라낸다.
배경이 단색이 아니면(야외컷·배경 있는 사진) 손대지 않고 원본을 쓴다.

모델 발이 화면 아래 끝에 닿는 사진이 많아서 처음엔 테두리 평균색으로 판정했다가 전부 실패했다.
최빈색 씨드 방식으로 바꿔서 유니클로·나이키·아임웹 모델컷 모두 0.2초 안에 깔끔하게 분리된다.

### 색과 패턴은 색상 칩에서 본다

모델컷에서 색과 패턴을 뽑으면 둘 다 틀린다. 크롭 안에 피부·머리·배경·그림자가 섞이기 때문이다.
실제로 유니클로 스트레이트진의 대표색이 `#cac9be`(배경/피부)로 잡혔고, 줄무늬 티셔츠 3종의
줄무늬 신호가 0.18~0.44로 무지 옷과 구별되지 않았다.

그래서 색상 칩이 있으면 **칩으로 대표색·팔레트·패턴을 모두 판단**한다 (`garment_view`).
칩은 옷 색만 있어서 깨끗하다. 같은 컬러웨이의 칩을 고르는 게 중요한데, 색 거리로만 고르면
대표색이 이미 배경색이라 엉뚱한 칩을 집는다. 그래서 **파일명의 숫자 코드를 먼저 맞춘다** —
`krgoods_69_482279_3x4.jpg` 와 `goods_69_482279_chip.jpg` 는 `69`, `482279` 를 공유한다.
코드가 같은 칩이 없으면 색 거리로 넘어간다.

| | 모델컷 기준 | 칩 기준 |
|---|---|---|
| 스트레이트진 대표색 | `#cac9be` (배경) | `#494f5f` (데님 네이비) |
| 레귤러치노 대표색 | `#b19873` | `#d5bd99` (베이지) |
| 줄무늬 소프트립T 줄무늬 신호 | 0.44 | 23.91 |
| 줄무늬 폴로B | 0.43 | 65.94 |
| 줄무늬 코튼셔츠 | 0.18 | 103.29 |
| 무지 SUPIMA T | 0.90 | 0.06 |

칩 기준으로 계산했을 때는 상품 카드에 "대표색 ... · 색상 칩 기준" 이라고 표시된다.
칩이 없는 사이트(나이키·아임웹)는 모델컷으로 계산하고 표시가 붙지 않는다.

### 패턴 태그

상품 카드마다 **무지 / 줄무늬 / 패턴** 버튼이 있다. **색상 칩에서 본 줄무늬만 자동으로 찍어주고**
(`pattern.from === 'chip' && kind === 'stripe'`), 나머지는 사용자가 고른다.

`analyze_pattern` 은 한 축으로는 밝기가 크게 오르내리는데 그 축과 직각인 줄 안에서는
일정하다는 성질로 줄무늬를 잡는다 (임계값 3). 칩에서는 무지 0.02~0.06 대 줄무늬 23~103 으로
자릿수가 다르게 갈리고, 세로줄(셔츠)/가로줄(티셔츠) 축도 맞게 나온다.

프린트·그래픽은 자동 판별하지 않는다. 상위 색 비중으로 잡아보려 했지만 칩에서도 무지 티셔츠의
top1 이 0.20~0.27 로 낮게 나온다 (음영·질감이 양자화되면서 여러 칸으로 쪼개짐). 사용자 태그로 둔다.

### 패턴 궁합 진단

네 항목(색 조화·명도 대비·채도 균형·전체 색 수) 점수는 대표색 기준이라, 패턴 옷은 따로 보정한다.
패턴 옷은 대표색 하나가 아니라 **비중 12% 이상인 색을 최대 3개까지** 팔레트로 쓴다.

| 상황 | 보정 | 조언 |
|---|---|---|
| 위아래 둘 다 줄무늬 | -22 | 줄 간격이 부딪혀서 하나는 무지로 |
| 위아래 둘 다 패턴 | -18 | 시선이 분산됨 |
| 한쪽 패턴 + 무지 색이 패턴 팔레트와 가까움 (RGB 거리 60 이하) | +7 | 가장 안정적 |
| 한쪽 패턴 + 무지 쪽이 무채색 | +4 | 패턴을 그대로 받아줌 |
| 한쪽 패턴 + 패턴에 없는 유채색 | -4 | 패턴 속 색에 맞추는 선택지를 제시 |

보정 후 0~100으로 자른다. 무지 조합끼리는 보정이 0이라 기존 점수가 그대로 유지된다
(회색+카키 93, 베이지+청바지 87, 흰+검정 86, 검정+검정 79, 남색+청바지 76, 형광주황+파랑 64, 빨강+초록 52).

| 패턴 조합 | 점수 |
|---|---|
| 네이비/흰 줄무늬 + 네이비 팬츠 | 100 |
| 네이비/흰 줄무늬 + 회색 슬랙스 | 97 |
| 그래픽 티 + 검정 팬츠 | 93 |
| 네이비/흰 줄무늬 + 카멜 팬츠 | 89 |
| 그래픽 티 + 초록 팬츠 | 83 |
| 줄무늬 + 줄무늬 | 57 |

실제 상품으로 돌린 결과 (유니클로).

| 조합 | 점수 | 패턴 궁합 |
|---|---|---|
| 줄무늬 소프트립T + 스트레이트진 | 100 | 패턴 안의 차콜과 하의 색이 이어짐 |
| 줄무늬 코튼셔츠 + 스트레이트진 | 97 | 하의가 무채색이라 패턴을 그대로 받아줌 |

## 점검 기록

360 / 390 / 768 / 1280px 을 헤드리스 크롬으로 렌더링하고 모든 엔드포인트에 잘못된 입력을 넣어
점검했다. 오류 7건, 모바일 6건, 불편 3건을 고쳤다. 모바일 페이지 높이가 5398 → 3941px 로 줄었다.

측정 방법과 항목별 원인·조치는 [AUDIT.md](AUDIT.md) 에 있다.

## 알아둘 점

- 유니클로·나이키·아임웹 쇼핑몰은 주소만 넣으면 된다. **무신사·네이버 스마트스토어·쿠팡·에이블리·
  지그재그는 주소로 안 된다** — 데이터센터 IP 를 막거나 화면을 JS 로 그린다.
  웹 버전의 **사진** 버튼으로 상품 사진을 올리면 된다 (끌어다 놓기·붙여넣기도 받는다).
  올린 사진은 배경을 자동으로 지운다 — 단색 배경은 바로, 휴대폰 사진은 사람 분리 모델로.
  왜 안 되는지는 [WEB.md](WEB.md) 에 갈라 적었다.
- 저장한 코디는 `localStorage` 에 있어서 이 맥의 이 브라우저에서만 보인다.
- 아임웹은 색상 옵션을 AJAX(`/shop/select_option.cm`)로 불러오므로 HTML에 옵션 색이 없다.
  갤러리 사진에서 색을 뽑는 방식으로 우회했다.
- 줄무늬 자동 판별은 색상 칩이 있는 사이트, 또는 올린 사진의 신호가 뚜렷할 때 된다.
  안 잡히면 카드에서 무지/줄무늬/패턴을 직접 고르면 된다.
- 아주 가는 핀스트라이프는 놓친다. 유니클로 스마트이지팬츠(스트라이프)가 0.88 로 무지로 잡혔다.
